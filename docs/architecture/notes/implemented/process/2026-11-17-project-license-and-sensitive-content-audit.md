# Agent Note: 统一项目许可与敏感内容审计

Status: implemented

## Problem

仓库公开，但此前仅携带部分上游许可，项目自身没有统一许可证。用户要求补齐项目许可，并检查目录结构中是否包含敏感内容。

历史审计：现有阅读室和媒体修复记录说明了上游绘图来源，保留其决定；尚无项目整体许可或凭据检查记录，当前记录与两者不重复。

## Decision

项目自身的代码和文档使用 MIT，版权主体为仓库维护者 douxiaohu，年份 2026。根目录 LICENSE、README 与前端包元数据统一声明。THIRD_PARTY_NOTICES.md 明确第三方例外：delineate 继续保留原 MIT 归属；Geist 字体继续使用 OFL-1.1，原许可随前端 public/licenses 分发。频道内容不因项目代码采用 MIT 而重新授权。

敏感内容检查使用官方 Gitleaks 8.30.1，在临时目录执行，下载包经官方 SHA-256 清单比对。当前源码从 Git 跟踪文件及未被忽略的新文件生成快照，避免将 node_modules 和虚拟环境当作项目源码。历史扫描遍历本地所有可达 refs 的完整历史，并补充检查历史敏感文件名，以及本地实际管理密钥的字节值是否出现在可达 Git blob 中。真实值不打印、不写入本记录。

扫描命令保留所有默认检测规则，使用 100% 脱敏报告，不通过排除整个测试目录来隐藏命中。原始工具报告与本机清单存入已忽略的 outputs/security-audit/，不提交 GitHub。

## Findings

审计基线为 34a1083：271 个 Git 跟踪文件、26 个可达提交（Gitleaks 遍历到 25 个非合并提交）。

| 范围 | 结论 |
| --- | --- |
| 当前源码 | Gitleaks 命中 5 个 generic-api-key，均位于 internal/config/config_test.go |
| Git 历史 | 命中同样 5 个测试值，首次加入于 da6d5d7；未发现其他凭据命中 |
| 人工复核 | 命中均为配置校验和引号解析测试中的固定占位字符串，不是实际部署密钥 |
| 当前与历史敏感文件名 | 未发现被跟踪的真实 .env、groups.yaml、数据库、私钥或凭据 JSON |
| 实际本地密钥比对 | 当前 .env 的管理密钥未出现在可达 Git blob 中 |
| 本地目录 | .env 含实际管理密钥，config/groups.yaml 和 SQLite 数据库属于本地运行资料，均已忽略且未跟踪 |
| 信息披露 | 历史架构文档出现本机用户名绝对路径，当前文档改为相对项目根目录；旧提交中的字符串仍存在 |
| 部署说明 | 发布记录中的网站域名、镜像哈希、备份目录和版本标识属于部署元信息；未发现其中包含凭据值 |

本地 .env 权限从 0644 收紧为 0600。忽略规则补充环境文件变体、SSH 目录、常见私钥/证书包、SQLite 文件及凭据 JSON，保留 .env.example 可提交。SECURITY.md 说明报告方式和实际忽略规则的边界。

## Alternatives considered

- 只给上游代码保留 MIT：不能覆盖项目自身代码，因此补根许可证并同步包元数据。
- 将所有资源统称 MIT：简洁，但会错误覆盖字体及频道内容的原始权利，因此明确第三方例外。
- 因 5 个测试命中排除整个测试目录：可以让工具显示零，但会丢失对后续测试文件真实凭据的检测，因此保留原始命中并人工分类。
- 为删除本机用户名路径重写并强推 Git 历史：能清除旧字符串，但该路径不是访问凭据，重写公开提交会打扰现有引用，因此仅修正当前文档并披露历史仍存在。

## Consequences

根项目的再使用条件清晰，原有第三方许可继续保留。新增的字体许可文件进入生产构建产物，README 的徽章和许可说明与代码元数据一致。

本次检查没有发现确认的真实密钥泄漏，但仍有需要保护的本地运行资料。规则匹配存在漏报和误报；本报告不涵盖不可达 Git 对象、远端已删除且本地未获取的提交、GitHub 外部附件/Issue、服务器文件或依赖漏洞。当前明文路径修复不删除旧历史记录。
