# Agent Note: 拾讯的自部署、发布与阅读能力边界

Status: implemented

## Problem

现有 Go 单实例应用已经提供公开阅读与独立管理中心，但站点网址写在分享代码中，发布验证依赖仓库外的临时脚本。Git 忽略规则没有同步覆盖构建与上传；媒体缓存只有单文件限制。读者没有收藏、阅读恢复或本站消息链接。旧架构路线图仍把 Python 阶段称为当前主干。

历史审计：[纸张阅读室](../feature/2026-11-17-editorial-assembly-reading-room.md)与[完整媒体分享](../bug-fix/2026-11-17-complete-media-and-paged-share-cards.md)部分重叠，继续保留其动效隔离、完整媒体与有界分页决定；[许可与敏感内容](../process/2026-11-17-project-license-and-sensitive-content-audit.md)的配置保护扩展到打包和部署，不更改许可与历史审计结论。

## Decision

保持 Go、React 和单 SQLite。公开配置接口只返回站点名称、描述和规范网址，不返回运行环境或凭据；规范网址由部署者设置，缺省时浏览器使用当前 origin，不信任请求 Host 生成外部链接。消息详情与列表、媒体使用相同的 enabled/public_visible 门禁。收藏只在本机存储消息 ID，显示内容时重新经过公开接口，因此私有化后不能继续通过收藏读取旧正文。

阅读进度保存 URL 与消息 ID，通过明确的继续阅读入口恢复；不在首次访问时强制跳页。分享保留正文、全部静态图和分页，每页附本站消息链接与二维码。四语言范围覆盖公开阅读界面，频道原文与后台运维文案保持原语言。

媒体缓存首次启用年龄策略时，通过一次性标记给予过期历史文件一个完整保留周期，避免直接按旧修改时间回收。媒体缓存按总容量和年龄回收，保留数据库消息。清理只操作本缓存命名格式的普通文件，不跟随符号链接；清理与下载、打开文件互斥，已打开的传输不中断。默认使用有限容量与保留时长，管理统计不泄露宿主路径。

发布工具兼容现有服务器的 Python 3.8，CI 以 3.8 / 3.12 验证数据库路径和备份工具，避免依赖只在维护机可用的新标准库方法。正式发布入口要求源码已提交、二进制 VCS 元数据与当前提交一致，并扫描实际构建产物，对上传清单逐文件校验，拒绝凭据、备份、运行数据与符号链接。使用 SQLite 在线备份，不回退到复制活跃主库。候选容器使用独立数据库且不采集生产来源，验证通过才替换生产容器；回滚镜像与运行环境保留，回滚不恢复数据库。默认 Compose 独立运行，服务器专用网络通过覆盖配置接入。

Go 漏洞扫描器固定为 v1.9.0，支持 Go 1.27 的语法；旧 v1.1.4 在 Linux SSA 构建时崩溃，不能作为通过或发现漏洞的依据。依赖安全门禁要求使用已修复的 Go 1.27.4、golang.org/x/net v0.62.0、Vite 6.4.6 与 Vitest 5.1.0。阅读包预算为 280 KiB，二维码与非中文词典各 32 KiB，详情页 12 KiB，Assembly 36 KiB，分享导出 16 KiB；按需资源不计入首屏阅读预算。Gitleaks 的新例外仅匹配配置测试文件和固定假值，不忽略整个 tests 目录。

## Alternatives considered

- 收藏正文快照：离线查看方便，但公开权限撤销后仍保留正文，因此仅存 ID，读取时重验权限。
- 默认强制恢复滚动：返回体验直接，但会覆盖显式检索和分享链接，因此提供明确继续阅读入口。
- 清理整个缓存目录：实现简单，但可能误删非缓存文件或正在写入的临时文件，因此限制文件命名并协调读写。
- 仅构建时注入站点网址：不需要接口，但自部署改域名必须重建镜像，因此采用仅含公开字段的运行时配置。
- 部署失败恢复旧数据库：能回到旧快照，但会丢失发布后新增消息，因此仅自动恢复镜像与配置。

## Consequences

部署增加正式工具与验证成本，阅读增加本机偏好数据；收藏不会跨设备同步。缓存回收后的旧媒体需要原 CDN 仍可访问才能重新获取。后台目前保持中文，公开界面提供简体中文、English、日本語与Español。

验证覆盖配置校验与字段白名单、消息详情撤权、缓存回收与并发打开、在线备份恢复、包内容边界、收藏恢复和四语言布局。发布前执行 Go 测试、前端单元测试、三尺寸浏览器测试、构建体积检查与敏感内容扫描。
