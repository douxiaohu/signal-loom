# Agent Note: 媒体完整显示与长文多图分享分页

Status: implemented

## Problem

用户反馈媒体组装偏慢、多图经常裁掉边缘，以及长文或多图分享排版错乱。实际源码中，多图缩略图使用 `object-fit: cover`，手机单图容器存在额外的 320px 裁剪；分享渲染器只取首张图片，以固定封面比例再次裁剪，并将正文限制在 13～17 行。

历史审计：现有[阅读室笔记](../feature/2026-11-17-editorial-assembly-reading-room.md)部分重叠，持有动效与 DOM 所有权的决定，继续保留并互链；没有已有分享导出的决定记录需要替代或归档。

## Decision

消息动画使用两倍时钟、更快的手部运动和打字，并优先展开媒体。单张卡片最迟在开始后的 3.2 秒恢复完整内容；交互立即完成、视口触发、已读缓存和 React 文本所有权保持不变。介绍区 Assembly 的速度不随消息调整。

单图、图库和视频均保留比例。图库图片使用 contain，手机单图取消外层高度裁剪；缩略图仍可点击打开原图。这里不以拉伸填满方格为目标。

分享渲染器按完整正文和附件顺序生成若干 PNG 页。按加载完成的字体测量换行，不再截断标题或正文；每页重复独立来源标识和页号，正文允许跨页，图片保留完整比例并整体放置，不裁剪源区域。优先使用 original_url，失败才回退到缩略图；仍无法加载的图片保留编号、位置和明确提示，不能静默漏图。

每一页 PNG 的页脚同时绘制站名和完整网站地址 `https://douxiaohu.duckdns.org`，复制当前页、单页下载与 ZIP 中的所有图片均携带网站入口。地址使用已确认的公网主页，不取当前页面 origin、路径或查询参数，因此本地预览生成的图片也不会带 localhost、筛选条件或管理路径。

每页逻辑上限 1080×2600，导出倍率 1.5，实际像素最多 1620×3900。图片逐张解码和绘制，页面逐页编码为 Blob 并释放光栅；长度增长表现为更多页，不表现为一个无限高的画布。短正文加单张长图可以按剩余空间等比放在同一页。

弹窗将 PNG 按宽度显示，内部可以纵向滚动，顶部工具栏和页码保持可达。多页支持前后翻页和复制当前页；单页下载 PNG，多页一次下载包含全部 PNG 的 ZIP，避免浏览器阻止连续下载。ZIP 使用标准 store 格式与 CRC32，无新依赖。关闭弹窗取消加载并撤销所有页面的 Blob URL，异步复制结果不跨页误报。

分享渲染器改为打开弹窗后按需加载，体积上限独立检查为 16 KiB；阅读脚本保持 260 KiB，Assembly 保持 36 KiB。

## Alternatives considered

- 一个超长 PNG：分享路径最接近原有功能，但长正文和多个长图会突破浏览器画布尺寸、光栅内存限制，且预览缩成不可读的小图，因此按有限尺寸分页。
- 多图做固定裁剪拼贴：图片排列紧凑，但仍会丢失截图、海报或长图边缘内容，与用户要求冲突，因此完整等比绘制。
- 保留首图并提示其余图片去看原文：实现较小，但不能完成多图分享，故不采用。
- 每页分别触发一次浏览器下载：不需要 ZIP，但会受到连续下载限制，也不便确认整套内容是否齐全，因此在多页时打包为一个 ZIP。

## Consequences

长文、多图会产生更多分享页，图片不会统一裁成封面。完整内容优先于单页紧凑度，用户可逐页复制或下载全部；失败的远端图片不会被误称为已完整导出。

回归覆盖横图、竖图、方图混排、65 段正文和末尾长 URL、原图失败回退、图片完全失败占位、单张长图、纯文字消息的空媒体字段、页码切换、复制当前页、ZIP 全部 PNG 和尺寸上限。浏览器测试核对 Canvas 实际绘制的文字、原图请求与无源裁剪的绘制参数；导出的 ZIP 还通过 Python zipfile 的 CRC 校验与逐页 PNG 尺寸检查。测试不依赖生产消息或修改业务数据库。
